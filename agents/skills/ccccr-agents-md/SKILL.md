# 编写与维护 AGENTS.md

参考范本：[mozilla-firefox/firefox AGENTS.md](https://github.com/mozilla-firefox/firefox/blob/main/AGENTS.md)。遵循 KISS：每一行都要能改变 agent 的行为，否则删掉。

## 何时使用

- 新建或修改 `AGENTS.md`、`CLAUDE.md` 等 agent 指令文件。
- 用户给出新约定（"以后都……"、"不要再……"），需要落到指令文件里。
- 指令文件变长、重复或过时，需要精简。

## 步骤

1. 读完整个目标文件，再动手；改之前确认要加的内容没有已有条目覆盖。
2. 有已有条目就改那一条，不新增重复条目。
3. 只改与本次需求相关的部分，不顺手重写其他章节。
4. 改完通读一遍，删掉不再成立或不影响行为的句子。
5. 向用户报告改了哪几条，不复述整个文件。

## 结构

- 一个 `#` 标题，下面直接写全局规则；其余按主题分 `##` 章节（如工具、代码风格、工作流）。
- 不写目录、背景介绍、项目简介；agent 能从代码读出来的东西不写。
- 子目录有独立约定时，在子目录放自己的 `AGENTS.md`，根文件只写一句"处理 `<dir>/` 时先读其中的 `AGENTS.md`"。

## 写法

- 用祈使句直接下指令：写"用 `rg` 搜索"，不写"建议考虑使用 `rg`"。
- 一条规则一个要点；规则不显然时，在同一条里用半句话给出原因。
- 硬性约束用 `MUST` / `NEVER`（或"必须" / "禁止"），只留给真正不能违反的规则，不滥用。
- 给出确切命令和参数，放进行内代码或代码块，不写"用合适的工具"。
- 写清楚例外和替代方案：禁止某做法时，同时说明该怎么做。
- 原则类条目可用加粗短语开头概括，后接解释，例如 `**引用名字，不引用位置。**`。
- 不用表情符号，不用空洞的形容词（"重要"、"优雅"、"最佳实践"）。
- 保持文件现有语言；同一文件内不中英混写规则正文。

## 禁止

- 禁止加入一次性任务的细节或本次对话的上下文。
- 禁止把 skill、README 或代码里已有的内容抄进指令文件；需要时只写指向它的一句话。
- 禁止为假想场景预写规则；出现过的问题才写进去。
